# Контекст проекта Daily Randomizer

> Файл для сохранения контекста между сессиями. Обновляется по результатам работ.

## Что это

Десктоп-приложение для случайного выбора ведущего дейли на работе. Запрос пользователя (2026-10-16):

- Приложение на Kotlin + Gradle + Spring, с графическим интерфейсом.
- При запуске открывается окно: окошко с именем, ниже кнопка «Крутить».
- В углу кнопка настроек → окно добавления/удаления имён.
- При нажатии «Крутить» имена крутятся «как в казино», по итогу выводится имя.

## Текущее состояние

**Готово и работает:**
- Полный UI: главное окно (`MainFrame`), диалог настроек (`SettingsDialog`), анимация прокрутки с замедлением (`SpinAnimator`), генерация последовательности (`SpinSequenceGenerator`).
- Хранение участников в JSON (`~/.daily-randomizer/names.json`) через `ParticipantStorage`.
- Бизнес-логика в `ParticipantService`: добавление с валидацией (пустое имя, дубликаты без учёта регистра), удаление, случайный выбор.
- Тесты: `ParticipantServiceTest` (7 кейсов), `SpinSequenceGeneratorTest` (6 кейсов). `./gradlew test` — зелёный.
- Сборка `./gradlew build` — зелёная.
- Headless-проблема решена: `SpringApplication(...).setHeadless(false)` в `main` (см. известные проблемы п.2).

**Ключевые решения:**
- Swing вместо JavaFX: для простого приложения Swing не тянет платформозависимых нативных зависимостей и работает с установленным Temurin 21. JavaFX потребовал бы отдельного артефакта под macOS.
- Spring Boot оставлен как контекст/DI (по требованию пользователя), UI стартует на EDT через `SwingUtilities.invokeLater` после `runApplication`.
- `application` плагин + явный `mainClass` (`DailyRandomizerApplicationKt`) добавлены в `build.gradle.kts` — без них задача `run` отсутствовала.
- Анимация: интервал растёт квадратично от 50 до 400 мс на 30 шагов — эффект замедления барабана.
- Один участник → имя выводится сразу без прокрутки; пустой список → предупреждение с подсказкой открыть настройки.

## Известные проблемы окружения

1. **Сеть в песочнице**: сборка из Claude-сессии требует `dangerouslyDisableSandbox` — иначе TLS-handshake к Maven Central падает (`Remote host terminated the handshake`).
2. **Headless — РЕШЕНО 2026-10-16**: корневая причина была в коде, а не в окружении. `SpringApplication.run()` по умолчанию выставляет `java.awt.headless=true` (метод `configureHeadlessProperty()` в Spring Boot), что ломает создание Swing-окон в любом терминале. Исправление в `DailyRandomizerApplication.kt`: явное `SpringApplication(...).setHeadless(false)` вместо `runApplication`. Подтверждение гипотезы: чистый `java /tmp/WindowTest.java` (без Spring) открывал окно, приложение с Spring падало везде. Гипотеза про Gradle-демон была неверной (демон мог усугублять, но не был причиной).
3. **Версии Gradle**: 2026-10-16 wrapper зафиксирован на 8.14 (`gradle wrapper --gradle-version 8.14`), чтобы совпадал с локальной установкой в IDEA. Полная сборка с тестами на 8.14 — зелёная. Настройка "Distribution" в IDEA влияет только на задачи из IDEA, а `./gradlew` в терминале всегда использует wrapper-версию из `gradle/wrapper/gradle-wrapper.properties`.
3. **Gradle user home**: предупреждение `WARNING Ignored custom Gradle user home location configured in Gradle user home: /Users/ruagbg3/.gradle/gradle.properties` — не критично, на работу не влияет.

## Пул участников (2026-10-16)

- `Participant.kt` — data class: name + inPool (по умолчанию true).
- `ParticipantService`: getPool() (только inPool), setInPool(), addAllToPool(), removeAllFromPool(), removeFromPool(), pickRandom() — из пула. Хранение — JSON со списком объектов {name, inPool}.
- `SettingsDialog`: кастомный ListCellRenderer — чекбокс слева от имени (только отрисовка). Переключение пула — MouseListener на JList: клик в левой зоне строки (40 px, константа `CHECKBOX_ZONE_WIDTH`) инвертирует флаг. Рендерер JList не интерактивен — ActionListener в нём не срабатывает и накапливался при каждом рендере. Кнопки «Добавить всех» / «Убрать всех» рядом с «Удалить выбранного».
- `MainFrame`: «Крутить» крутит только пул; после победы — кнопка «ПЕРЕКРУТИТЬ» + появляется «Провести» (убирает победителя из пула, сбрасывает на placeholder «X провёл дейли»). Один в пуле → сразу победитель без прокрутки.

## Казино-тема (2026-10-16)

Стиль в духе реального казино:
- `CasinoTheme.kt` — палитра и стилизация: зелёное сукно (felt), золото (gold), красная кнопка-фишка с золотой окантовкой и декоративными полосками, тёмный дисплей слот-машины с золотой рамкой, reelFont для барабана.
- `FeltBackgroundPanel.kt` — фон главного окна: градиент сукна + виньетка. Является корневым контентом окна (иначе серые участки contentPane торчат по краям).
- `SlotReel.kt` — барабан слот-машины: вертикальная лента имён, прокручивается СВЕРХУ ВНИЗ (offset в ячейках, дробная часть — плавный переход), затемнение сверху/снизу как цилиндр, золотые линии-маркеры по центру, альфа-затухание дальних ячеек. Лента ЗАЦИКЛЕНА во время прокрутки (индекс по модулю) — интрига сохраняется. `showWinner()`: режим победителя — имя 46pt жирное с циклическим переливом цвета (HSB-оттенок от goldHue) и свечением. Фейерверк УБРАН из SlotReel — перенесён в FireworksOverlay. `fitFont()` — авто-подгон размера шрифта плейсхолдера под ширину рамки (минимум 12pt, отступы TEXT_PADDING=16) — длинный текст «X провёл дейли…» больше не обрезается.
- `FireworksOverlay.kt` — полноэкранный салют ПОВЕРХ ВСЕГО ОКНА (glass pane через `rootPane.glassPane`), не перехватывает клики (isOpaque=false). 14 разрывов по 48 частиц, скорость разлёта 90, затухание 4.8 с, таймер 50 мс, сам скрывается когда разрывы затухли. Запуск: `fireworksOverlay.launch()` из MainFrame (onSpinFinished и случай pool.size==1).
- `SpinAnimator.kt` — непрерывная анимация ~60 FPS (dt по System.nanoTime), скорость 18→1.2 ячеек/с квадратично; цель прокрутки = 2*size - 1 ячеек (1 полный круг + докрутка до последнего элемента = победителя, лента зациклена по модулю size) — остановка ВСЕГДА на победителе, иначе в центре остаётся не то имя. Рандомизация длительности — через случайную стартовую скорость (+0–8 ячеек/с).
- `MainFrame` — кнопка «КРУТИТЬ» во время прокрутки: disabled + текст «КРУТИТСЯ...». Победитель через `slotReel.showWinner(name)`.
- `SettingsDialog` — тёмный фон, золотые рамки, тёмный список; панель добавления на BorderLayout (поле CENTER, кнопка EAST — иначе FlowLayout обрезал кнопку при малом окне). Вкладки — НЕ JTabbedPane (Aqua на macOS рисует вкладки по-своему: белый фон, серый текст, кастомный BasicTabbedPaneUI ненадёжен и вкладки пропадали). Сделано на кнопках + CardLayout: createTabButton (свой BasicButtonUI-paint: выбранная — felt/gold/textLight, невыбранная — feltDeepest/goldDark/gold), selectTab() переключает карточки, нижние кнопки по вкладке (полный набор на «Участниках», только «Закрыть» на «Теме» через createCloseOnlyPanel).
- `CasinoTheme.styleSmallButton` — кнопки перекрашены в самый тёмный оттенок сукна `feltDeepest` (0x062A18, при нажатии `feltDeepestPressed` 0x041F11) с золотой рамкой — выделяются на фоне feltDark. Кастомный BasicButtonUI-paint: Swing иначе затирает фон при нажатии/наведении. Текст при наведении — goldBright.
- Все цвета/шрифты собраны в `CasinoTheme` — менять стиль в одном месте.

## Способ запуска (решение 2026-10-16)

**Пользователь хочет fat jar** — запускать приложение как `java -jar`, без Gradle.

- Продакшн-запуск: `./gradlew bootJar` → `java -jar build/libs/daily-randomizer-1.0.0.jar` (с 2026-10-16 версия 1.0.0). JVM поднимается из терминала пользователя, Gradle-демон не участвует в рантайме — headless-проблема не проявляется. Проверено: jar стартует (Spring поднимается).
- Отладка: `./gradlew run` из IDEA/терминала. ВАЖНО: задача `run` форкает JVM из Gradle-демона — если демон был поднят из Claude-сессии (без WindowServer), окно падает с `HeadlessException` даже в терминале пользователя. Решение: `./gradlew --stop` перед запуском пользователем.
- Доступ к WindowServer у терминала пользователя подтверждён чистым тестом `java /tmp/WindowTest.java`.
